# Backend Setup Instructions

## Starting the Spring Boot Application

The tracing page requires the backend API to be running to fetch real system logs. If the backend is not available, the frontend will show sample mock data.

### Prerequisites
- Java 17 or higher
- Maven 3.6+

### Starting the Backend

1. **Using Maven Wrapper (Recommended):**
   ```bash
   ./mvnw spring-boot:run
   ```
   
   On Windows:
   ```cmd
   mvnw.cmd spring-boot:run
   ```

2. **Using IDE:**
   - Open the project in your IDE (IntelliJ IDEA, Eclipse, VS Code)
   - Find the main application class (usually `AutodocxApplication.java`)
   - Run the main method

3. **Using JAR file:**
   ```bash
   # First compile the project
   ./mvnw clean package
   
   # Then run the JAR
   java -jar target/autodocx-*.jar
   ```

### Verification

Once started, the backend should be available at:
- **Base URL:** http://localhost:8081
- **Health Check:** http://localhost:8081/actuator/health
- **API Logs Endpoint:** http://localhost:8081/api/logs

### Configuration

The application uses profile-based configuration:
- **Development Profile:** `application-dev.yml`
- **Production Profile:** `application.yml`

### Database

The application uses H2 in-memory database by default:
- **H2 Console:** http://localhost:8081/h2-console
- **JDBC URL:** jdbc:h2:mem:testdb
- **Username:** sa
- **Password:** (empty)

### Troubleshooting

1. **Port 8081 already in use:**
   - Change the port in `application.yml`: `server.port: 8082`
   - Update the frontend API calls to use the new port

2. **Java version issues:**
   - Ensure you have Java 17 or higher installed
   - Check with: `java -version`

3. **Maven issues:**
   - Ensure Maven is properly installed
   - Try: `./mvnw clean install`

4. **CORS issues:**
   - The backend is configured to allow requests from:
     - http://localhost:3000 (Create React App default)
     - http://localhost:5173 (Vite default)
     - http://localhost:8081 (Backend port)

### Logs Location

When the backend is running, it will automatically generate logs that can be viewed in the tracing page:
- Application logs are captured by the `LoggingInterceptor`
- Database queries are logged when `logging.level.org.hibernate.SQL=DEBUG`
- Custom business logic logs are generated by services

### API Endpoints

The tracing page uses these endpoints:
- `GET /api/logs` - Fetch paginated logs
- `GET /api/logs/advanced-search` - Search logs with filters
- `POST /api/logs/analyze-errors` - AI-powered error analysis
- `GET /api/logs/health-metrics` - System health metrics
- `GET /api/logs/patterns` - Detect log patterns
