### The Overarching Goal

To create an automated system that can intelligently generate and maintain high-quality documentation for a software project, mimicking the workflow of an expert human developer.

---

### Phase 1: Intelligence Gathering & Planning

This phase is handled by two specialized agents that create a high-level "map" of the project and a "blueprint" for the documentation.

**Agent 1: The Summary Agent (The "Surveyor")**

*   **Primary Goal**: To explore the codebase and create a compressed, high-density summary of its key components without overflowing the context window.
*   **Key Actions**:
    1.  **Check for Existing `README.md`**: Its first action is to look for existing documentation. This determines if the overall goal is to *generate* a new document or *update* an existing one.
    2.  **Identify Core Components**: It uses the **Hub Score algorithm** (`findHubNodes`) to identify the most important "orchestrator" classes that represent the core business logic.
    3.  **Explore and Compact**: For each important node, it performs a two-step process:
        *   It fetches the full source code using `get_code`.
        *   It immediately calls the **`summarise_code`** tool. This tool uses an internal LLM call to replace the full source code in memory with a structured JSON object containing the node's purpose, public methods, and dependencies. This is the crucial **Context Compaction** step that prevents memory overflow.
*   **Output**: A "memory" containing a high-level, structured summary of the project's most important components.

**Agent 2: The Planner Agent (The "Architect")**

*   **Primary Goal**: To create a structured, machine-readable plan for the documentation.
*   **Key Actions**:
    1.  **Analyze the Summary**: It reviews the compacted context provided by the Summary Agent and the existing `README.md` (if any).
    2.  **Formulate a Plan**: It creates a logical plan for the documentation. Instead of just a text list, it uses the **`add_section`** tool to build a formal plan, creating `DocumentationSection` objects.
*   **Output**: A structured plan, managed by a `PlanManager`, that looks like this:
    *   `[ { title: "Core Logic: Agent Service", purpose: "...", nodes: ["class_Agent"] },`
    *   `  { title: "API Reference: AgentController", purpose: "...", nodes: ["class_AgentController"] }, ... ]`

---

### Phase 2: Content Generation

This phase is handled by one or more worker agents that execute the plan created in Phase 1.

**Agent 3: The Documentation Agent (The "Writer")**

*   **Primary Goal**: To write a detailed, accurate markdown section for a *single* item in the plan.
*   **Key Actions**:
    1.  **Receive a Task**: It is given one `DocumentationSection` object from the plan (e.g., "Document the Agent Service").
    2.  **Focused Deep Dive**: It uses its tools (`get_code`, `getNeighbourSubgraph`) to explore only the nodes specified in its task. Because the overall context is small and focused, its analysis is fast and accurate.
    3.  **Generate Markdown**: It writes a self-contained markdown snippet for its assigned section.
*   **Parallel Execution**: This agent can be instantiated multiple times in parallel (using a `sendMessageBulk` approach), with each instance working on a different section of the plan simultaneously for maximum efficiency.
*   **Output**: A collection of individual, high-quality markdown documentation fragments.

---

### Phase 3: Final Assembly & Editing

This final phase is handled by a specialized agent that ensures the final output is polished and professional.

**Agent 4: The Editor Agent (The "Finisher")**

*   **Primary Goal**: To assemble the individual documentation fragments into a single, coherent, and well-structured `README.md` file.
*   **Key Actions**:
    1.  **Gather Fragments**: It collects all the markdown snippets generated by the Documentation Agent(s).
    2.  **Structure and Refine**: It does not write new technical content. Instead, it:
        *   Writes a high-level project introduction.
        *   Organizes the fragments into a logical order.
        *   Adds transition sentences and boilerplate sections (like "Installation" and "Usage").
        *   Ensures a consistent voice and formatting throughout the document.
*   **Output**: The final, complete, and professional `README.md` file.
